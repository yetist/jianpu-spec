# 番茄简谱脚本规范 v2.0（草案）

> 状态：**Draft 1**（2026-10-21）  
> 性质：设计草案，不是最终规范。语法细节仍可能调整。  
> 基底：本仓库 `v1/01-简介.md` ～ `v1/05-建议.md` 所描述的 v1.0 规范。  
> 参考实现：`bin/jps2svg.py`（v1.0 语法的本地渲染器）。

---

## 1. 为什么需要 v2.0

v1.0 的核心价值是**用纯文本、以接近打字的速度录入简谱**，这一点必须保留。
但 v1.0 在早期实现中做了大量让步，导致规范里积累了许多“补丁”：

- 所有记号都堆在音符后面，顺序、含义、边界依赖上下文；
- 节拍切分固定按四分音符，6/8、9/8 等必须用 `~` / `^` 手工纠正；
- 连音线、延音线、连音符共用 `()`，多连音靠“自动算音符数 + 自动缩时值”；
- 跳房子、临时拍号、力度偏移都写成 `"..."` 或 `+` 手工微调；
- 隐藏休止符用 `8`、节奏音符用 `9`，和音高数字混在一起；
- 降号用 `$`、还原号用 `=`，与通用记谱习惯不一致；
- 注释只能用整行 `#`，而 `#` 同时又是升号；
- 歌词靠“一个字符对一个音符”，休止符、延音线都要用 `@` 占位；
- 多声部、临时声部、行内声部用 `Q1/Q2`、`{bz}`、`{dsb}`、`&sbf`、`8`、`|*` 组合实现；
- 分页、位置避让等排版问题被塞进内容语法；
- 大量符号用拼音缩写 `&xx` 表示，且码表只存在于图片里。

v2.0 的目标不是“再补几个符号”，而是把 v1.0 中**内容、时间、排版、扩展**四层重新分开，
让语法可预测、可实现、可校验、可迁移。

## 2. 设计原则

1. **语义优先**：谱面内容、时间结构、排版指令分离；排版指令不得改变音乐含义。
2. **显式优于隐式**：拍号、拍组、多连音比例、声部范围、反复结构都显式书写，不靠猜测。
3. **上下文内单一含义**：在曲谱行、歌词行、描述头各自的上下文内，一个符号只表示一个含义；跨上下文（如曲谱的 `~` 延音线 vs 歌词的 `~` 合字）允许复用，但必须在规范中显式区分。
4. **保留输入效率**：以 ASCII 为主、记号短、空格可省略、单行即一个系统。
5. **可校验**：小节时值、声部对齐、反复配对、连音线配对都能在解析期检查并给出定位。
6. **自动排版是渲染器的责任**：连音线避让、力度位置、跳房子高度、分页、跨行连线由渲染器自动处理，语法不提供 `+` 手工偏移。
7. **可扩展**：标准命令封闭，扩展命令使用 `x-` 命名空间；未知扩展可安全忽略。
8. **可迁移**：提供 v1.0 → v2.0 的确定性映射和转换器；v2.0 不追求与 v1.0 源码二进制兼容。
9. **国际化**：UTF-8；中文、英文、混排歌词使用同一套音节模型；符号名使用稳定的英文/ASCII 名，不用拼音缩写。
10. **单一时间模型**：渲染器和播放器共享同一套 onset/duration/measure 模型，避免“看起来对、播放不对”。

## 3. 相对 v1.0 的主要变化

| 领域 | v1.0 | v2.0 | 解决什么问题 |
|---|---|---|---|
| 注释 | 行首 `#` | `%` 行注释、`%{...%}` 块注释 | `#` 归还给升号；支持行尾注释 |
| 描述头 | `V/B/Z/D/P/J/X/H` 单字母 | `@version`、`@title`、`@composer` 等完整键名 | 不再靠重复键和位置猜语义 |
| 调号 | `D: $E` | `@key 1=bE`；小调写 `@key 6=A` | 与简谱“1=C / 6=A”习惯一致 |
| 拍号 | `P: 4/4 (2/4 1/4)` | `@time 4/4`；变拍用行内 `\time(2/4)` | 拍号变化有明确位置 |
| 拍组 | 固定四分音符，`~`/`^` 补救 | 由拍号推导，`@beats 3+3` 可覆盖 | 6/8、9/8、5/8 不再需要手工切分 |
| 音符 | `1-7`、`0`、`8`、`9` | `1-7`、`0`、`x`；隐藏休止写 `0\hidden` | 数字不再承担“隐藏/节奏”语义 |
| 变化音 | `#` `$` `=` | `#` `b` `n` | 与通用记谱一致 |
| 时值 | `/`、`.`、`-` | 保留，但明确“基本音符=四分；`-` 每次 +1/4” | 与时值模型一致，可校验 |
| 延音线 | `()` | `~` | 与连音线分离 |
| 连音线 | `()` | `( ... )` | 保留，但不再和延音线混淆 |
| 多连音 | `(y ... )` 自动算 | `3:2{ ... }` 显式比例 | 不再“自动猜时值” |
| 倚音 | `[..]` / `[h..]` | `[..]` 前倚音；`\after{..}` 后倚音 | 不再用 `h` 这种位置相关标记 |
| 力度/表情 | `&mp`、`<`、`>`、`!`、`+` | `\mp`、`\<`、`\>`、`\!`，位置自动 | 去掉手工 `+` 偏移 |
| 其他记号 | `&xx` 拼音缩写 | `\trill` 等英文名；`x-` 扩展 | 码表可读、可扩展、可校验 |
| 跳房子 | `[` `]` `[/` `[+` | `\|1.` `\|1,2.` ... `:\|` / `\|]` | 结构语义化，闭合自动 |
| 跳转 | `&dc`、`&ds`、`&fine` 等 | `\dc`、`\ds`、`\fine`、`\coda`、`\tocoda` | 与反复结构统一建模 |
| 临时拍号 | `\|"p:x/y"` | `\|\time(x/y)` | 不再把 DSL 塞进字符串 |
| 隐藏小节线 | `\|/`、`\|*` | `\|\hidebar`、`\|\phantombar` | 排版操作显式化 |
| 临时声部 | `{bz ...}`、`{dsb ...}` | `\voice(2, above, brace){ ... }` | 声部号、位置、括弧样式显式 |
| 行内声部 | `&sbf` + `8` + `\|*` 填充 | 临时声部块自动确定起点和范围 | 不再手工填充 |
| 分页 | `[fenye]` | `\pagebreak`；默认自动分页 | 排版与内容分离 |
| 歌词占位 | `@` 跳过每个休止符 | 只对可发声音符对齐，休止/延音/倚音自动跳过 | 大幅减少 `@` |
| 歌词连字 | `~` | `~` 保持 | 语义明确 |
| 英文歌词 | `/` 分词 | `-` 音节分隔；空格分词 | 与音符 `/` 脱钩 |
| 歌词注释 | `"..."`，空格要写 `_` | 行首 `"..."` 是段落标签；`\text("...")` 是注释；空格直接写 | 不再需要下划线代替空格 |
| 多行歌词括号 | 歌词里写 `{` `}` | 同声部多行歌词自动加大括号 | 去掉内容里的排版符号 |
| 手工偏移 | `+` 数量 | 自动避让；必要时 `\offset(n)` | 渲染器负责排版 |
| 错误处理 | 基本无 | 分级诊断、定位、严格/宽松模式 | 可维护、可测试 |

## 5. 兼容性说明

- v2.0 **不要求**现有 v1.0 文件直接可解析。推荐用转换器生成 v2.0 文件后人工复核。
- 解析器可以用 `@version` 区分版本：`@version 2.0` 走 v2；若文件以 `V: 1.0` 开头，可按 v1 兼容模式处理，但不属于本规范。
- 转换器中无法自动判定的地方（`( )` 是延音线还是连音线、`(y ... )` 的具体比例、`&xx` 未收录记号）必须在输出中加注释标记，交由人工确认。

## 6. 仍然开放的问题

以下问题建议在草案评审时定稿：

1. `-` 增时线定义为“每次 +1/4”是否符合所有简谱习惯？是否还需要 `\extend(1/8)` 这种显式延长？
2. `[...]` 是否保留为前倚音糖衣，还是统一写成 `\grace{...}`？
3. 声部编号是否只允许整数？是否需要命名声部（`V(lead):`）？
4. 默认“一行一系统”是否保留？`@layout.systems auto` 是否应成为默认？
5. 歌词行是否允许 `|` 作为对齐屏障，以便在跳房子内部写不同歌词？
6. 和弦标记 `\chord("...")` 是否进入核心，还是放在扩展？
7. 多连音 `N:M{}` 的 `N` 是否允许非整数比（如 `7:4` 可以，`2.5:2` 不可以）？
8. 是否需要在核心支持打击乐谱表、鼓谱多行、无音高音符的更多记号？
9. 跨行连音线/延音线自动续接，是否还需要显式 `\tieContinue` 作为逃生舱？
10. `@layout.*` 的键集合是否应独立成“排版规范”，而不是塞在描述头里？
11. 单声部柱式和弦是否需要专门语法？目前建议用多声部/`\voice` 表示；如果要加，需避免与倚音 `[]` 和块 `{}` 冲突。
12. 调式写法用 `@key 6=A`（调式主音落在 6）是否足够直观？是否需要同时支持 `@key 1=C` + `@mode minor` 这种更显式的两段式写法？
