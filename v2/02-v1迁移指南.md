# v1.0 → v2.0 迁移指南

> 本文描述如何把 v1.0 `.jps` 迁移到 v2.0。  
> 迁移不是“字符替换”：v1 有些写法本身有歧义，必须结合上下文判断。  
> 转换器的输出必须附带一份“待人工确认”清单。

---

## 1. 总体策略

1. **先解析，再生成**：用 v1 兼容解析器把源文件解析成结构（描述头、Q/C 行、音符、记号、块），不要直接正则替换。
2. **逐行转换**：`Q` 行 → `V` 行；`C` 行 → `L` 行；`[fenye]` → `\pagebreak`。
3. **结构化重写**：`(y ... )` → `N:M{}`；`{bz ...}`/`{dsb ...}` → `\voice(...){}`；`[...]` 跳房子 → `|1.`。
4. **歧义标记**：无法确定的 `()`、`&xx`、`J:`、`D:`、`P:` 辅助拍号，输出 `% TODO:` 注释，并在报告中列出。
5. **用 v2 解析器自检**：至少检查小节时值、声部小节数、歌词锚点数。
6. **人工复核**：重点看延音线/连音线、跳房子、临时声部、歌词 `@`。

## 3. 行与声部映射

| v1.0 | v2.0 | 说明 |
|---|---|---|
| `Q:` | `V1:` | 单声部 |
| `Q1:` | `V1:` | 编号声部 |
| `Q2:` | `V2:` | |
| `Q1"主旋律":` | `V1:` + `@voice 1 name="主旋律"` | 声部名移到描述头 |
| `C:` | `L:` | 依附最近 `V` |

| `C2:` | `L(2):` | 明确附着声部 2 |

| 空行 | 空行（保留） | 在 `layout.systems=line` 下分隔系统 |
| `[fenye]` | `\pagebreak` | 行级命令，放在声部行末 |

v1 的多声部/临时声部：

| v1.0 | v2.0 |
|---|---|
| `{bz ...}` | `\voice(2, above, brace, small){ ... }` |
| `{dsb ...}` | `\voice(2, above, brace){ ... }` |

| 声部名 `Q2"伴奏":` | `@voice 2 name="伴奏"` |

## 5. 歧义处理

### 5.1 `( ... )`：延音线还是连音线？

v1 用同一对括号表示：

- 延音线（tie）：同音相连，延长时值；
- 连音线（slur）：不同音相连，表示连贯。

v2 分开为 `~` 和 `( ... )`。转换规则：

1. 若括号内**恰好两个音符**（忽略增时线 `-` 和内部小节线），且音高、八度、变化音完全相同，且没有其他音符/休止：判定为延音线，输出 `第一个音符~ 第二个音符`。
2. 若括号内所有音符都是同一音高、且相邻：可以判定为延音线链，输出 `1~ 1~ 1`。
3. 其他情况：判定为连音线，保留 `( ... )`。
4. 若括号内包含不同音高，但其中两个相邻同音高音符明显是延音：拆成 `(1 2~ 2 3)` 这种混合形式；转换器应尽量保留括号外层，内部同音对用 `~`。
5. **报告**：所有被判定为延音线的组都列入“请确认”清单，因为同音连音线在音乐上也可能是有意的分句。

示例：

```
v1:  (2 - | 2)
v2:  2~ | 2

v1:  (3/ 2/ 1/)
v2:  (3/ 2/ 1/)
```

### 5.2 `(y ... )`：多连音比例

v1 的 `(y ... )` 不写比例，渲染器自动把组内总时值缩到“不超过原总时值的 2 的幂”。
转换器必须把这个隐含规则显式化：

1. 计算组内写成总时值 `S`（以四分音符为 1）。
2. 取 `T = 2^floor(log2(S))`。
3. 若 `T == S`：v1 实际没有缩放，输出普通音符，去掉 `(y ... )`。
4. 否则比例 `N:M = S:T`，用组内最小时值单位化为整数，约分。
5. 输出 `N:M{ ... }`。

例子：

| v1 组内 | 写成总时值 S | T | 比例 | v2 |
|---|---|---|---|---|
| 3 个八分 | 1.5 | 1 | 3:2 | `3:2{1/ 2/ 3/}` |
| 5 个十六分 | 1.25 | 1 | 5:4 | `5:4{1// 2// 3// 4// 5//}` |
| 7 个八分 | 3.5 | 2 | 7:4 | `7:4{...}` |
| 6 个八分 | 3 | 2 | 3:2 | `3:2{...}` |
| 4 个八分 | 2 | 2 | 无缩放 | `1/ 2/ 3/ 4/` |

注意：v1 的自动算法本身可能不符合原谱意图；转换器必须为每个 `(y ... )` 生成一条 TODO，提示人工确认比例。

### 5.3 `~` 和 `^`：节拍切分

v1 的 `~`/`^` 是因为“拍组固定按四分音符”而增加的补丁。v2 的拍组由拍号推导，绝大多数情况直接删除即可。

需要保留“跨拍连接/强制断开”的少数情况：

- `~` → `\beam{...}`，把需要连起来的音符包进去；
- `^` → `\nobeam`。

转换器应先按 v2 的拍组规则计算一遍；如果删除 `~`/`^` 后减时线分组与 v1 输出不同，再生成 `\beam`/`\nobeam` 并报告。

示例：

```
v1:  5 3/2/1/~ |
v2:  5 \beam{3/ 2/ 1/} |
```

### 5.4 `&xx` 未知记号

v1 的符号表以图片形式存在，很多 `&xx` 没有文字定义。转换器：

- 已知的按第 4 节映射；
- 未知的输出 `\x-v1-xx`，并在行尾加 `% TODO: 确认 &xx 的含义`；
- v2 渲染器遇到未知 `\x-` 时忽略并告警，不会破坏其余谱面。

### 5.5 跳房子

v1：

```
|["1."(1' - 1'/)0/ 3/.3// :|]["2." (1' - 1'/)0/ 3/.2// |]/
```

v2：

```
|1. 1' - 1'/ 0/ 3/. 3// :| |2. 1' - 1'/ 0/ 3/. 2// |]
```

规则：

- `[` 在小节线处、后面跟 `"..."`：是跳房子开始；
- 标签是数字（可带逗号）：输出 `|1.`、`|1,2.`；
- 标签不是数字：输出 `|\house("...")`；
- `]`：删除（v2 自动闭合）；
- `[/`：删除（v2 自动在反复结束/终止线/下一个跳房子处闭合）；
- `[+`：删除 `+`（v2 自动避让）；
- 跳房子内的 `(`/`)` 仍按第 5.1 节处理。

### 5.6 `&fine` 写在音符上

v1 示例中有 `1)&yc - ||/&fine` 这种写法：`&fine` 附着在音符/小节线上，参考实现甚至把音符上的 `&fine` 当作力度 `f` 处理（实现 bug）。

转换规则：

- 若 `&fine` 在小节线后：输出 `\fine`；
- 若 `&fine` 在音符后：把它移到最近的小节线后，输出 `\fine`，并报告；
- 同理处理 `&dc`、`&ds`。

### 5.7 `P:` 的辅助拍号

v1 的 `P: 4/4 (2/4 1/4)` 只说明“可能出现的辅助拍号”，没有位置。v2 的 `\time(...)` 必须写在小节线上。

转换器输出主拍号，并把辅助拍号列在 TODO 注释中，由人工放到正确小节。

### 5.8 `J:` 的拍值单位

v1 文档只说“数字表示每分钟的拍子数”，没有说以什么音符为一拍。转换器默认 `4=BPM`，并在报告中提示：6/8 曲目可能需要 `8=BPM`。

### 5.9 `D:` 的大小调

v1 的 `D: A` 不区分 A 大调还是 A 小调。v2 用：

- `@key 1=A`：A 大调；
- `@key 6=A`：A 小调。

转换器默认输出 `1=A`，并提示人工确认。

## 6. 歌词迁移

### 6.1 `@` 占位

v1 的 `@` 表示“跳过一个音符”。v2 的锚点规则不同：

- 休止符、隐藏休止、增时线、倚音、延音线后续音符**自动跳过**；
- 只有“可发声音符但不想写歌词”的情况才需要 `_`。

转换算法：

1. 按 v1 规则得到音符/休止序列；
2. 按 v2 规则得到锚点序列；
3. 逐个 `@` 对齐：
   - 若该 `@` 对应的是休止/延音线后续/增时线：删除；
   - 若对应的是可发声音符：输出 `_`；
4. 剩余的歌词字符按 v2 音节规则重新切分。

### 6.2 其他歌词符号

| v1.0 | v2.0 | 说明 |
|---|---|---|
| `~` | `~` | 合字，不变 |
| `/`（英文分词） | `-` | 音节分隔；如果原意是单词间空格，改成空格 |
| `"1."`（行首） | `"1."` | 段落标签，保留；v2 允许标签内有空格 |
| `"注释"`（歌词前） | `\text("注释")` | v2 不再用双引号做音节注释 |
| `_`（歌词注释中的空格） | 空格 | v2 直接写空格 |
| `{` `}`（多行歌词括号） | 删除 | v2 自动画大括号 |
| `@` | 见 6.1 | |

示例：

```
v1: C: 月亮在白@莲花般的云朵里@穿行，@晚风吹来一阵阵@快乐的歌@
v2: L: 月 亮 在 白 _ 莲 花 般 的 云 朵 里 _ 穿 行 ， _ 晚 风 吹 来 一 阵 阵 _ 快 乐 的 歌
```

（具体哪些 `@` 删除、哪些变 `_`，要以对应 Q 行的锚点为准；上面只是示意。）

英文：

```
v1: C: hear/the/peo/ple/sing
v2: L: hear the peo-ple sing
```

或按单词对齐（每个单词一个原子）：

```
v2: L: hear the people sing
```

`-` 只放在一个单词内部；单词之间用空格。

## 7. 转换器实现步骤

建议实现为独立的 `jps1to2` 工具，而不是在 v2 渲染器里做兼容分支。

```
1. 读取文件，检测 v1：
   - 以 "V: 1.0" 开头，或存在 "Q:"/"C:" 行。
2. 分离描述头和主体。
3. 转换描述头（第 2 节），生成 @version 2.0。
4. 逐个逻辑行处理：
   a. "#" 注释 -> "%" 注释；
   b. "[fenye]" -> "\pagebreak"；
   c. "Q..." -> "V..."；提取声部名 -> @voice；
   d. "C..." -> "L..."；
   e. 先扫描 Q 行中的 {bz}/{dsb}，递归转换；
   f. 用 v1 tokenizer 切分音符/小节/块；
   g. 转换记号（第 4 节）；
   h. 处理 ()/(y)（第 5 节）；
   i. 处理跳房子/反复/跳转（第 5.5/5.6 节）。
5. 歌词转换（第 6 节），需要与 Q 行锚点配对。
6. 生成 v2 文件 + report.txt：
   - 所有 TODO；
   - 所有被判定的延音线；
   - 所有多连音比例；
   - 未知 &xx；
   - 需要人工放置的辅助拍号；
   - 大小调待确认。
7. 如果环境中有 v2 解析器，运行一次并汇总错误/告警。
```

转换器**不得**静默丢弃信息；无法映射的内容必须保留为 `\x-v1-...` 或 TODO 注释。

## 8. 完整转换示例

### 8.1 简单示例（排排坐）

v1：

```jps
#============================以下为简谱头部定义==========================
B: 排排坐
B: 极简示例歌谱
Z: 佚名词曲
D: C
P: 4/4
J: 120
S: 牵风纸鸢根据网络资料记谱
#============================以下开始简谱正文============================
Q: 1 1 2 - | 3 3 2 - | 5 5 3 1 | 2 3 2 - |
C: 排排坐，吃果果，幼儿园里朋友多，
Q: 3 3 2 - | 6, 1 2 - | 5 5 3 1 | 2 3 1 - ||
C: 朋友多，来唱歌，唱起歌来多快活。
```

v2：

```jps
@version 2.0
@title 排排坐
@subtitle 极简示例歌谱
@lyricist 佚名
@composer 佚名
@key 1=C
@time 4/4
@tempo 4=120
@source 牵风纸鸢根据网络资料记谱

V1: | 1 1 2 - | 3 3 2 - | 5 5 3 1 | 2 3 2 - |
L: 排 排 坐 ， 吃 果 果 ， 幼 儿 园 里 朋 友 多 ，
V1: | 3 3 2 - | 6, 1 2 - | 5 5 3 1 | 2 3 1 - |]
L: 朋 友 多 ， 来 唱 歌 ， 唱 起 歌 来 多 快 活 。
```

说明：

- `Z: 佚名词曲` 被拆成 `@lyricist` + `@composer`；如果不确定，改成 `@credit 佚名词曲`。
- 两行 `Q` 之间没有空行；v2 通过“`V1` 重复出现”自动分成两个系统。
- 歌词不再需要为空拍写 `@`，因为 `-` 不是锚点。

### 8.2 复杂片段（延音线 + 多连音 + 力度）

v1：

```jps
Q: 3&mp (5,./ 6,//) | 1 - | 3./ 2// 1// 5,// 6,/ | (y 1/ 2/ 3/) 4 |
C: 那时@候妈妈没有土地
```

v2：

（假设 2/4、首小节为弱起；这里只展示记号转换。）


## 9. 人工复核清单

转换完成后，至少检查：

- [ ] `@key` 是大调还是小调（`1=` vs `6=`）。
- [ ] `@tempo` 的拍值单位是否正确（4= 还是 8=）。
- [ ] 所有被判定为延音线的 `()` 是否正确。
- [ ] 所有 `N:M{}` 的比例是否符合原谱。
- [ ] 跳房子的起止是否落在正确的小节线。
- [ ] 临时声部块的起点、长度、括弧样式是否正确。
- [ ] 遗留的 `&sbf`、`8`、`|*` 是否已删除，且声部仍对齐。
- [ ] 歌词 `@` 是否只转换成了必要的 `_`。
- [ ] 英文歌词的 `/` 是否改成了 `-` 或空格。
- [ ] 所有 `\x-v1-...` 是否已经替换或确认可以忽略。
- [ ] 小节时值校验是否全部通过。
- [ ] 跨行连音线是否不再需要手工写第二个 `)`。

## 10. 兼容性边界

- v2 解析器**不保证**直接接受 v1 文件；推荐先转换。
- 如果必须兼容 v1，建议在解析器入口根据 `V: 1.0` 或 `Q:`/`C:` 自动切换到 v1 兼容前端，再走统一的内部模型。
- 兼容前端只应作为过渡，不应成为 v2 规范的一部分。
- v2 不保留 `#` 注释、`$` 降号、`=` 还原、`8`/`9`、`&xx`、`|/`、`|*`、`[fenye]` 这些 v1 写法；它们只出现在迁移映射表中。
